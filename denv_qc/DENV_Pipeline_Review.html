What the Pipeline Does Well

Pre-flight Validation

  • Checks all 8 required tools are in PATH
  • Validates input directory existence
  • Tests write permissions (output + sam_files)
  • Verifies reference FASTA + GenBank files exist

Reference QC

  • Validates FASTA contains only IUPAC bases
  • Checks GenBank format (LOCUS + FEATURES)
  • Verifies FASTA ↔ GenBank ID match
  • Auto-creates indices (.fai, .dict) if missing

BAM Validation

  • samtools quickcheck on raw + sorted BAM
  • Alignment count > 0 required to proceed
  • Validates at multiple pipeline stages

Annotation Pipeline

  • Custom SnpEff database from GenBank
  • Structured field extraction via SnpSift
  • Gene-level impact aggregation across samples
  • Pre-built DENV1-4 reference indices included

Issue #1: fastp Runs with All Defaults

Current Pipeline

fastp -i R1 -I R2 -o trimmed_R1 -O trimmed_R2
# That's it. No other parameters.
ParameterPipeline (default)
Quality thresholdQ15
Min read length15 bp
Sliding window trimdisabled
Overlap correctiondisabled
N-base filtering5 N max (default)

Recommended

fastp -i R1 -I R2 -o trimmed_R1 -O trimmed_R2 \
  --qualified_quality_phred 20 \
  --length_required 50 \
  --cut_front --cut_tail \
  --cut_window_size 4 \
  --cut_mean_quality 20 \
  --correction \
  --overlap_len_require 30 \
  --detect_adapter_for_pe
Impact on our data: The R2 imaging artifact bases (Q13–14 at positions 24, 59, 82) would be retained with default Q15 threshold. Sliding window trimming is essential to remove these.

Issue #2: No Duplicate Removal

The Problem

  • PCR-amplified libraries produce optical and PCR duplicates
  • Our DENV data shows 4–21% duplication rates
  • Duplicates inflate coverage estimates
  • Duplicates bias variant allele frequencies
  • Can cause false variant calls or mask real low-frequency variants
The pipeline has no duplicate marking or removal step at any stage — not in fastp, not via samtools markdup, not via Picard MarkDuplicates.

Recommended Fix

Add after BAM sorting, before variant calling:

# Option A: samtools
samtools markdup \
  sample.sorted.bam \
  sample.dedup.bam

# Option B: picard (GATK companion)
gatk MarkDuplicates \
  -I sample.sorted.bam \
  -O sample.dedup.bam \
  -M sample.dedup_metrics.txt

For amplicon data, consider samtools markdup -S to handle supplementary alignments.

Issue #3: No Mapping Quality Filtering

Current Pipeline

samtools view -S -b -T ref.fa input.sam > output.bam
# No -q flag (min MAPQ)
# No -F flag (flag filtering)
All reads pass through, including:
  • Unmapped reads (MAPQ=0)
  • Multi-mapped reads (low MAPQ)
  • Secondary/supplementary alignments
  • Human host reads that weakly map to DENV

Recommended Fix

samtools view -b -T ref.fa \
  -q 20 \
  -F 0x904 \
  input.sam > output.bam

# -q 20   : min MAPQ 20
# -F 0x904: exclude:
#   0x4   = unmapped
#   0x100 = secondary alignment
#   0x800 = supplementary alignment
Critical for clinical samples — plasma RNA contains human host reads. Without MAPQ filtering, host-derived reads with spurious low-quality alignments to DENV contaminate the pileup.

Issue #4: GATK Uses Wrong Ploidy

Current Pipeline

gatk HaplotypeCaller \
  -R ref.fa -I sample.bam -O raw.vcf \
  --standard-min-confidence-threshold-for-calling 30 \
  --min-base-quality-score 20
  # No --ploidy flag!
  # Default = diploid (ploidy 2)
GATK defaults to diploid calling. This models heterozygous genotypes (0/1) that do not exist in a haploid viral genome. This can produce spurious heterozygous calls and miss true variants.

Inconsistency in Pipeline

Variant CallerPloidy SettingCorrect?
bcftools call--ploidy 1Yes
GATK HaplotypeCallerdefault (2)No

Fix

gatk HaplotypeCaller \
  -R ref.fa -I sample.bam -O raw.vcf \
  --standard-min-confidence-threshold-for-calling 30 \
  --min-base-quality-score 20 \
  -ploidy 1

Issue #5: ivar Consensus Parameters

Current command

samtools mpileup -d 1000 -A -Q 0 sample.bam | ivar consensus -p sample -q 20 -t 0

Problems

ParameterValueIssue
-t 0freq = 0Any majority base called, even at 10% support
-m10 (default)Only 10x min depth for calling — may be too low for clinical samples
-Ainclude anomalous pairsIncludes orphan/discordant reads
-d 1000max depth 1000May downsample high-coverage amplicon regions

Recommended

samtools mpileup \
  -d 10000 -Q 0 \
  sample.bam | \
ivar consensus \
  -p sample \
  -q 20 \
  -t 0.5 \
  -m 20
  • -t 0.5: Majority-rule consensus (base must have ≥50% support)
  • -m 20: Min 20x depth to call a base (else N)
  • Remove -A: Exclude anomalous pairs
  • -d 10000: Higher ceiling for amplicon data

Issue #6: No VCF Filtering Step

Current Flow

GATK HaplotypeCaller → raw.vcf
↓ (no filtering)
SnpEff annotation → annotated.vcf
Raw variant calls go directly to annotation. No quality filtering means false positives, strand bias artifacts, and low-confidence calls are annotated and reported as real variants.

Recommended: Add Variant Filtration

gatk VariantFiltration \
  -R ref.fa \
  -V raw.vcf \
  -O filtered.vcf \
  --filter-expression "QD < 2.0" \
  --filter-name "LowQD" \
  --filter-expression "FS > 60.0" \
  --filter-name "StrandBias" \
  --filter-expression "MQ < 40.0" \
  --filter-name "LowMQ" \
  --filter-expression "DP < 20" \
  --filter-name "LowDepth"

# Then filter to PASS only
bcftools view -f PASS filtered.vcf \
  > pass.vcf

Issue #7: No Primer Trimming

The Problem

  • Our DENV data is PCR-amplified WGS
  • Amplicon primers are sequenced as part of the reads
  • Primer sequences do not reflect the actual sample — they are synthetic
  • Variants in primer-binding regions will be masked by the primer sequence
  • Can also cause false consensus errors at primer junctions
The pipeline has no ivar trim step. This is standard for any amplicon-based viral sequencing workflow.

Recommended Fix

Add after alignment, before variant calling:

ivar trim \
  -b primers.bed \
  -i sample.sorted.bam \
  -p sample.trimmed \
  -q 20 -m 50 -s 4 -e

# Requires a BED file of primer positions
# -q 20: min quality
# -m 50: min length after trimming
# -s 4:  sliding window for quality
# -e:    include reads without primers
Dependency: Requires the primer scheme BED file used for amplicon generation. If not available, this step cannot be performed, which is a limitation of the upstream wet lab documentation.

Issue #8: Incomplete Coverage Metrics

Current Metrics

  • Average coverage depth per sample
  • N-count in consensus FASTA
  • Total bases in consensus
  • Coverage depth plot (per-position)
Average depth alone is misleading. A sample with 500x average could have 0x coverage over 20% of the genome — and the pipeline would not flag this.

Should Also Report

MetricWhy It Matters
% genome at ≥10xMinimum for reliable consensus
% genome at ≥30xMinimum for reliable variant calling
% genome at ≥100xConfident minor variant detection
Median depthMore robust than mean
% on-target readsHost contamination indicator
Evenness of coverageAmplicon dropout detection

These are easily computed from the existing samtools depth output.

Additional Issues

FastQC reports are never evaluated
Reports are generated but not parsed. No automated pass/fail gate. A sample with catastrophic quality would still proceed through the pipeline.
Unused/redundant scripts
sam2consensus_test2.py and sam2consensus_test2_ivar.py are in the package but never called by run_pipeline.py. Creates confusion.
fastp JSON reports not parsed
fastp generates detailed JSON with adapter rates, quality distributions, and pass/fail metrics — the pipeline ignores all of it.
No multi-sample summary QC
No MultiQC or equivalent aggregation. Reviewing 40 individual FastQC + fastp reports manually is impractical.

Overall Verdict

Architecture: Good

  • Modular Python design
  • Correct tool selection
  • Good pre-flight and reference validation
  • Proper annotation pipeline
  • Pre-built DENV1–4 references

Parameterization: Insufficient

  • 4 critical issues that directly affect consensus accuracy
  • Multiple steps run with defaults instead of appropriate thresholds
  • Missing standard steps (dedup, MAPQ filter, VCF filter)
  • Not production-ready for clinical amplicon data without modifications
Recommendation: The pipeline provides a solid foundation but requires the modifications outlined in this review before being used for the DENV Nepal dataset. The most impactful changes are: (1) explicit fastp parameters, (2) duplicate removal, (3) GATK -ploidy 1, and (4) VCF filtering.
